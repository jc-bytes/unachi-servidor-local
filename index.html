05 / Opciones técnicas

Un equipo físico para la universidad.

El equipo guarda los datos y ejecuta la aplicación dentro de la universidad. El personal se conecta desde sus computadoras por la red local.

Qué debe resolverse

    ¿Qué software instalaríamos en el equipo?

    Registros relacionados

    PostgreSQL para proyectos, investigadores, unidades y resultados. Base de datos.

    Usuarios y permisos

    Auth para ingresar; políticas para decidir quién ve o modifica cada registro. Hay que configurarlas. Auth.

    Documentos

    Storage para archivos privados. La base guarda referencias y metadatos; también se pueden enlazar documentos existentes. Storage.

    Aplicación e informes

    Se desarrollan los formularios, validaciones y formatos del equipo. Metabase Open Source es una opción adicional para tableros, con sus propios recursos y permisos. Metabase.

    Supabase autoalojado es una opción de software en este equipo. Se instala localmente; no requiere contratar el plan administrado de Supabase. También se puede usar PostgreSQL con una aplicación propia. Formularios, informes, migración y capacitación se presupuestan aparte.

    Servidor: ¿Linux, Windows o Mac?
    SistemaUso que evaluaríamosQué verificar
    Linux en PC o máquina virtualPrimera opción a evaluar para servicio continuo con Docker Engine.Soporte del equipo, discos SSD, red, actualizaciones y restauración.
    WindowsReutilizar infraestructura institucional con una máquina virtual Linux, si el equipo la administra.Recursos de la VM, licencias del anfitrión y configuración de red.
    Mac / Apple SiliconEquipo existente o piloto, si el equipo técnico lo conoce.Contenedores ARM64, almacenamiento, arranque y operación continua.

    Criterio técnico propuesto, no resultado de una prueba. La guía oficial contempla las plataformas; recomienda 4+ núcleos, 8+ GB RAM y 80+ GB SSD para la pila. La aplicación y los datos necesitan recursos adicionales. Requisitos de Supabase.

    Docker Desktop tiene condiciones diferentes para educación y entidades gubernamentales. Confirmar la clasificación de UNACHI antes de presupuestarlo; no se incluye una licencia en este estimador. Condiciones de Docker.

    Primer paso recomendado: inventario de infraestructura y prueba con datos de muestra. Una base PostgreSQL con una aplicación propia también es una alternativa local si no se necesita toda la plataforma Supabase.

    AñoBase e índicesDocumentosSSD orientativoPor disco de respaldo

    Disco objetivo = 1.30 × [80 GB para servicios + base final + archivos finales]. El crecimiento de los datos se aplica al inicio de cada año. Se mantiene el mismo equipo durante el período y se comprueba su capacidad para el volumen final.

    El selector redondea el SSD calculado a una capacidad comercial de al menos 512 GB. RAM de planificación: 16 GB hasta 15 personas simultáneas; 32 GB hasta 50; 64 GB para más. Son reglas ilustrativas del estimador, no requisitos oficiales ni resultados de pruebas. La CPU, las consultas y otros servicios también influyen.

    Respaldo: dos discos de 2 TB para rotación. Cada uno debe almacenar dos versiones completas de la base y los documentos al final del período. Definir copias automáticas, retención y una ubicación separada; verificar la restauración.

    Electricidad = W / 1000 × 730 horas × tarifa. Soporte = horas mensuales × tarifa por hora. Subtotal del período = compra inicial + meses × electricidad, soporte y otros gastos.

    Falta cotizar: aplicación, migración, integración con SIGPRI, capacitación, impuestos, entrega a David, instalación, licencias aplicables, red, climatización, ampliaciones, redundancia y reemplazo de equipos o baterías. Los importes en cero no significan que esos trabajos sean gratuitos.

    Referencia de software: Linux + Docker Engine + Supabase autoalojado o PostgreSQL. El equipo técnico debe validar la instalación y los permisos. Los precios de hardware corresponden a las referencias de la sección Equipo.

    Salir con un primer paso claro.

    Proponemos probar un informe prioritario con un conjunto pequeño de datos autorizados.

    Acuerdos de la reunión

    Lo que comprobaría el piloto

    Que los datos se pueden reunir, revisar y convertir en un informe útil.

    1. Elegir un informe y revisar sus campos.
    2. Preparar una muestra autorizada y verificar los datos.
    3. Generar el informe y compararlo con una revisión manual.
    4. Acordar qué ajustar antes de ampliar el alcance.

    Con este alcance se podrán estimar el trabajo, el tiempo y los recursos. El análisis de patrones o minería de datos puede evaluarse después.
